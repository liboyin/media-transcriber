# T7: Store and worker

**Outcome:** Implemented in `acbfc49`, with review fixes in `c4a2b97`, `b995efc` and `5fb9689`. The gates passed, every mutant was killed, and the group review ended with no blocking findings.

Outcome: the SQLite job and failure store, job states and outcomes, failure categories, retention, and restart recovery with the interruption cap. Also the worker that runs one job at a time with one resident model (DESIGN 5.7 to 5.11, M8, M17, M18). Includes the activity and progress record that `/health` reads.

Freshness during decoding and publication follows DESIGN M18: the worker checks the marker again between chunks, and progress alone does not refresh the check.

The worker calls `run_pipeline` from [T3](T3.md) and the staging functions from [T6](T6.md), and maps their exceptions to failure categories.

Map only `MediaNotFoundError` to the category `missing`. It subclasses `FileNotFoundError`, but other `FileNotFoundError`s mean something else. Starting a missing `ffmpeg` binary raises one, and so does `publish_srt` when the SRT's directory is missing. Those belong to `internal` and `filesystem`. Check the specific staging exceptions before a generic `OSError`.

Paths: `media_transcriber/`, tests, DESIGN. Dependencies: T3, T6.

## Origin and boundary

Accepted for implementation on 2026-11-18, grouped with [T8](T8.md) (HTTP API), which depends on it. This file holds the [group plan](#group-plan).

- **Intent:** implement the service's state and its single worker. That covers the job and failure records (DESIGN 5.7, 5.8) and the processing of one job (5.5). It also covers restart recovery and the fatal exit (5.9), the marker pause (5.10), and the worker's side of health (5.11, M17, M18). The record that `/health` reads is in memory and published as immutable values, so the API never touches the share (5.1).
- **Dependencies:** T3, T6, T4 and T5 for the adapters that the worker loads. DESIGN 5.1 to 5.11, A2, A5, and decisions M8, M9, M17, M18, M20, M21 and M25. The collector's `store.py`, `worker.py` and `api.py` at `9c1b957` are the reference patterns (A2).
- **Implementation direction:**
  - `pipeline.py` (M25): `run_pipeline(media, load_model, language, checkpoint, clock)`. It calls `load_model` after decoding and before transcription, and `PipelineResult` gains `load_seconds`. The tests move to the loader.
  - `store.py`: as the collector's store, with one connection per thread, one `BEGIN IMMEDIATE` transaction per write, and the same handling of a failed transaction and a failed rollback.
    - Tables `jobs` and `failures` in a `STRICT` schema with a version, in WAL mode.
    - A job holds the path, the requested tag, the engine's code and the profile. It also holds the state, the current phase, the outcome, the SRT path, the timestamps, five durations and an interruption count.
    - `submit` deletes the jobs whose `finished_at` is past the retention in the same transaction, and keeps failures.
    - `next_job` returns the oldest queued job. `start_job`, `set_phase` and `finish_job` move a job through 5.7.
    - `finish_job` records a failure in the same transaction. A `done` job deletes the uncleared failures of earlier jobs for the same path (5.8).
    - `recover` returns each `running` job to `queued` and counts the interruption. At the third, it fails the job with an `internal` failure in the job's last recorded phase.
    - Reads: `get_job`, `list_jobs`, `list_failures`. Writes: `clear_failures`, `clear_failure`. `check` takes the write lock and commits nothing.
    - A job's representation embeds its uncleared failure, or null.
  - `worker.py`: one `Worker` that runs on one thread.
    - Its loop recovers, then repeats a step. A step checks the marker, pauses while it is missing without changing any record, and takes the next queued job.
    - A job runs DESIGN 5.5: staging, decoding, model, transcription, rejection and publication. The worker records each phase in the store before it starts it. A `done` job ends `transcribed` or `existing`.
    - The loader passed to `run_pipeline` loads the profile only if it is not resident. It drops the resident model before it loads another (5.3).
    - The decoding checkpoint checks the marker again when the last check is older than an interval. The publication checkpoint checks it at every call. Both record progress (M18).
    - A pure function maps a phase and an exception to a category. It follows this task's compact entry, and the assumptions below.
    - An error that escapes the handling of a job, including every store error, ends the worker's run. The worker then marks itself failed and passes the error once to a fatal callback (5.9). The service's callback (T8) pauses and exits.
    - `stop` ends the loop after the current job. `wake` ends an idle wait early.
    - `Activity` and `StagingCheck` are immutable values that the worker replaces whole, so another thread reads a consistent record. `Activity` holds the activity, whether it touches the share, the job, the start and the last progress. The resident profile's name is also readable.
    - A pure function decides whether the last marker check is stale for an activity (M17).
- **Decisions within DESIGN's latitude (assumptions):**
  - Categories by phase:
    - `MediaNotFoundError` gives `missing` in any phase, and `StagingUnavailableError` gives `filesystem`.
    - `RejectedTranscriptionError` gives `rejected` in the phase `rejection`.
    - Every error while loading gives `model`, also an unknown profile or engine.
    - `DecodingError` and `EmptyAudioError` give `decoding`.
    - `PathOutsideRootError` and every other `OSError` in staging and publication give `filesystem`.
    - Everything else gives `internal`, which includes an error raised during transcription. Evidence: DESIGN 5.8 defines `model` as a failed load or an unavailable device, and an engine error during transcription cannot be told apart from a defect.
  - A failure's message is the exception's type and text, such as `DecodingError: ffmpeg exited ...`.
  - The phase is persisted so that the interruption cap fails a job in the phase where it stopped. A store error raised inside the loader propagates through `run_pipeline` as a fatal error, not as a job failure.
  - The transcription duration includes serialization. The other durations follow `PipelineResult` and the worker's own timing of publication. The queue wait runs from submission to the last start. A failed job records the durations that it measured.
  - Defaults, which A5 calls starting values, follow the collector. The marker is checked during decoding at most every 10 seconds. The idle wait is 30 seconds, the paused wait 5 seconds and the staleness limit 120 seconds. The fatal pause is 60 seconds, the interruption cap 3 and the retention 7 days. The idle wait stays below the staleness limit, so an idle worker stays fresh.
  - Activities `idle`, `paused`, `staging`, `decoding` and `publishing` touch the share. `loading` and `transcribing` do not (5.11).
  - The submission computes the engine's language code, and the job keeps it. The API (T8) validates the tag first.
- **Compatibility surface:** the database schema is new, so no layout is preserved (A1). `run_pipeline`'s signature changes, and its only caller is the worker, because the benchmark (T9) does not exist yet. The marker name, the SRT naming and the `NEVER` policy are unchanged. No HTTP contract exists yet.
- **Non-goals:** the HTTP API, the settings, the composition of the service and the process exit itself (T8). The benchmark (T9). Cancellation and automatic retry (DESIGN section 2). The removal of stage directories left by an abrupt exit (5.6).
- **Validation:** unit tests of the store against a database in `tmp_path`, with an injected clock. Worker tests run real staging on `tmp_path` and real ffmpeg on synthetic WAV audio, with `FakeModel` and a fake adapter. They cover these cases:
  - Every state transition and outcome, and the category of every mapped exception.
  - The `existing` preflight before any decoding or model work, and residency across jobs and profiles.
  - The pause while the marker is missing, without a changed record.
  - A marker that disappears during decoding and during publication, which fails the job `filesystem`.
  - Retention, supersession and recovery with the cap.
  - A fatal store error, the activity record through a job, and the staleness rule.
- **Mutation evidence:** a missing marker publishes nothing and changes no record while paused (data loss on an unmounted share). A job is acknowledged `done` only after publication or a preflight hit (incorrect acknowledgement). Recovery requeues a running job and fails it at the cap (restart loop). A store error ends the worker instead of becoming a job failure (incorrect acknowledgement). Staleness applies during share activities and not during transcription (M17). Retention never deletes an unfinished job (data loss).
- **Done:** the three gates, the review, a closed record, and DESIGN's architecture section. A run against the real share is a host check (T2, after T8 and T11).

## Review

One Codex CLI session, `gpt-6.2-sol` at high effort through `dispatch.py`, reviewed T7 and T8 as one integrated group. The range ran from `badc878` to the final candidate. The review skill change in the user's commit `a5f7062` was out of scope. The commits were reviewed before a history rewrite, which folded the reviewer configuration into `a5f7062` and squashed the last fixes into `5fb9689`. Each tree below matches the tree that was reviewed. Every integrity snapshot comparison matched.

- First assessment of `badc878..d84fb96`: 5 Blocking and 4 Non-blocking findings. All were validated and fixed in `c4a2b97`:
  - Blocking: the old model stayed alive while another profile loaded, through a local reference and MLX's `ModelHolder` (DESIGN 5.3).
  - Blocking: a symlink that appeared at the SRT path during inference let publication write outside the root (DESIGN 5.2).
  - Blocking: media removed at the last checkpoint left an SRT without its media (M20).
  - Blocking: a stop during queue selection still started the job.
  - Blocking: a decoder blocked past the grace outlived the service process (DESIGN 5.9).
  - Non-blocking: share loss before the first chunk failed `decoding` rather than `filesystem`. A schema mismatch made `/health` return 500. An inherited `WEB_CONCURRENCY` stopped uvicorn. A non-string `default` in the profiles file raised `TypeError`.
- Follow-up 1 of `d84fb96..c4a2b97`: 2 Blocking and 2 Non-blocking findings, all validated and fixed in `b995efc`:
  - Blocking: a decoder could start after the kill's scan.
  - Blocking: inference that returned after abandonment still published.
  - Non-blocking: the health getter briefly held the model. A share lost during inference failed `missing`.
- Follow-up 2 of `c4a2b97..b995efc`: 1 Blocking finding, validated and fixed by the hook that `5fb9689` contains. Abandonment during the final media check still published. Also 1 Non-blocking finding, fixed: a load began after the phase write.
- Follow-up 3 of the hook: 1 Blocking finding. Abandonment during `StagedFile`'s own checks still linked. Any in-memory check leaves a gap before the syscall, so the main agent asked the user. The user chose a publication lock with a bounded wait, which `5fb9689` contains. Also 1 Non-blocking finding, fixed: an abandoned job recorded the `model` phase.
- Follow-up 4 of the lock: no blocking findings. One Nit on the `abandon` docstring was fixed, and `5fb9689` contains that fix. That change is docstring-only, so the verdict and the mutation evidence were reused, and the gates were rerun.

No finding is deferred.

## Limitations

- A publication whose link stalls on the share for more than 5 seconds can still finish after abandonment. Recovery then ends the job `existing`, which the user accepted.
- No regression test covers the health getter's former hold on the model. The race needs line tracing to reproduce.
- A path that changes between the second resolution and the link is not defended against, as T6's boundary accepts.
- Python-level isolation only: the network guard does not cover ffmpeg.
