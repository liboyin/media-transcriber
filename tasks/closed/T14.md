# T14: Take test results from pytest's reports in mutate.py

**Outcome:** In review.

Ad-hoc change requested by the user on 2026-11-18, from the friction that [T8](T8.md#mutation-evidence) recorded.

## Origin and boundary

During T8, `mutate.py` marked a mutant INVALID although both selected tests failed through their assertions. It counted every output line that starts with `ERROR` as an errored test. pytest prints captured log records in that form, such as `ERROR    media_transcriber.api:api.py:150 ...`, so a test that logs an expected error made a genuine kill look invalid.

- **Intent:** decide a run's results from pytest's own reports, never from its output, which can contain any line.
- **Dependencies:** none.
- **Implementation direction:** the plugin that `.agents/skills/adversarial-review/references/mutate.py` injects records each failed phase from `pytest_runtest_logreport`, which sees the final report after every `makereport` wrapper, also a project's own. The test body counts as `FAILED`, and setup or teardown as `ERROR`. `pytest_collectreport` records a collection failure as `ERROR`. `run_tests` reads these results from the plugin's report file instead of from pytest's output.
- **Decisions within the latitude (assumptions):** a failed setup or teardown is an errored test, as pytest's own summary calls it. The evidence lists results without pytest's one-line messages, which the failure details already give.
- **Compatibility surface:** the verdict rules are unchanged. In the evidence, each failed result is now `FAILED <test>` or `ERROR <test>`, without pytest's trailing message.
- **Non-goals:** any other verdict rule, and the shared tools in `agent-workflow-common`, which parse no pytest output.
- **Validation:** a new test logs a multi-line error and prints a line, both shaped like pytest's `ERROR` summary. It then fails through its assertion under a mutant, which must count as `KILLED`. A second new test pairs an assertion failure with a failed teardown, and requires `INVALID` from the teardown's `ERROR` result alone. A third has a project hook turn a skipped setup into an error, which must also count.
- **Mutation evidence:** a genuine errored test still invalidates a run, and a captured log line does not.
- **Done:** the three gates, the review, and this record.
