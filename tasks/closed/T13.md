# T13: Clone the shared tools over SSH

**Outcome:** Implemented. The gates passed, two mutants were killed, and the review found nothing.

## Origin and boundary

An ad-hoc change requested by the user on 2026-11-18. The user had switched the persistent checkouts of agent-workflow-common and pathlib-extensions to SSH remotes, and asked for the creation hook to clone over SSH as well.

- **Intent:** the creation hook clones agent-workflow-common from `git@github.com:liboyin/agent-workflow-common.git`, so that a new checkout can push. A failed clone tells the user to load the GitHub key into the SSH agent on the host.
- **Dependencies:** `postCreateCommand.sh` records GitHub's host keys before the hook runs, so the clone neither prompts nor trusts an unverified key.
- **Implementation direction:** change the URL in `.devcontainer/setup-agent-tools.sh` and add the message while keeping the clone's exit status. Update the hook's test and the README.
- **Decisions within DESIGN's latitude (assumptions):** VS Code forwards the host's SSH agent while the creation hook runs, as it does for terminals. This is unverified until a container is created on a new `dev_persist` volume.
- **Compatibility surface:** the creation hook. An existing checkout is reused unchanged, whatever its remote.
- **Non-goals:** changing the remote of an existing checkout, and any other part of the hook.
- **Validation:** the hook's tests with the clone stubbed. They check the SSH URL, the propagated exit status and the message.
- **Done:** the gates, the review and this record. The first creation on a new volume is a host check in T2.
