# T1: Governance framework and development base

**Outcome:** Implemented. The gates passed in the devcontainer image on arm64, and the review is pending.

## Origin and boundary

An ad-hoc change requested by the user on 2026-11-17, after DESIGN was accepted at `cd86eab`. The user chose approach A of three: governance plus a runnable development base, rather than governance documents alone or a full equivalent of `youtube-collector` including a production image. The user asked to be told every adjustment to the governance framework.

- **Intent:** adopt the governance of `youtube-collector`, which ClipboardTTS shares, adapted as [DESIGN section 11](../../DESIGN.md#11-engineering-standards-and-governance) and [section 9](../../DESIGN.md#9-deployment-and-development-environment) require. Add a devcontainer and a Python skeleton on which the three gates pass.
- **Dependencies:** DESIGN decisions M10 (devcontainer by default, host checks per run) and M15 (no CUDA machine yet).
- **Implementation direction:** copy each file from `youtube-collector` at `9c1b957` and apply the listed substitutions. Write no rule from scratch.
- **Decisions within DESIGN's latitude (assumptions):**
  - Python 3.14 (A3). On 2026-11-17, PyPI listed cp314 wheels for macOS arm64 and Linux aarch64 for ctranslate2 4.9.0, mlx 0.32.4, onnxruntime 1.32.0, av 19.0.2, tokenizers 0.23.3, torch 2.15.0 and numba 0.68.1.
  - No runtime dependency yet. Each engine, FastAPI and pathlib-extensions arrives with the task that uses it.
  - The devcontainer has no real-data variant, because real data is reached only by host checks.
  - The Dockerfile has no runtime stage until T10.
- **Compatibility surface:** none. The repository had no code, settings or on-disk layout.
- **Non-goals:** application code, the production CUDA image and Compose service (T10), the Mac launchd setup (T11).
- **Validation:** the three gates in the devcontainer image, the documentation check, a scan for leftover references to `youtube-collector`, and a test that the devcontainer mounts no host data.
- **Done:** the gates, the review, this record. Container persistence checks go to [T2](../open/T2.md).

## Implementation

Commits `87f9b2c` to the commit that adds this record, on branch `t1-governance`.

These are the adjustments to the governance of `youtube-collector`. Every other rule is copied unchanged.

| Area | `youtube-collector` | This repository |
|---|---|---|
| AGENTS environment | Stop unless in a Docker container | Stop unless in the devcontainer, or in a host check that the user authorized for this run. DESIGN section 9 owns the definition |
| AGENTS host data | Staging share, Firefox profile, SQLite volume, REAL DATA devcontainer | Staging share, model weights directory, video library. Never write into the video library. The devcontainer mounts no host data |
| AGENTS authorized actions | Each run against real YouTube, and `docker compose down -v` | Each host check |
| AGENTS test isolation | No YouTube | No model hub, no real model, no accelerator. ffmpeg only on test-owned synthetic audio |
| AGENTS gates | `mypy youtube_collector` | `mypy media_transcriber`, run in the devcontainer |
| AGENTS honest verification | No Docker daemon in the devcontainer | Same, plus a host check names its host and whether it used a real accelerator |
| STYLE glossary, host check | Needs a Docker daemon | Needs a Docker daemon, a real accelerator or real host data |
| Review skill, areas to scrutinize | SQLite, worker isolation, marker, publication, resources, paths, yt-dlp and captions | SQLite queue, API isolation from the share, marker, `NEVER` publication, model residency and ffmpeg processes, resources, paths in the staging root, engine fakes |
| `mutate.py`, `worktree_gates.py`, `check-coverage.sh` | `youtube_collector` | `media_transcriber` |
| `agent-workflow.json` dispatch safety | No YouTube, `.env`, browser profiles, share or SQLite volume | No real model, accelerator, video library, model weights, share or `.env` |
| Devcontainer | Layers on the production Compose file, plus a REAL DATA variant | One standalone Compose file with two named volumes, and no variant |
| Dockerfile | `base`, `build`, `runtime`, `dev`, with Deno | `base`, `build`, `dev`, without Deno |
| Test harness | Network guard, process exits, threads, loopback servers, service lifecycle | The same without the service lifecycle, which T8 adds back |
| Tasks | T1 to T61 | T1 closed, and T2 to T11 open |

Other changes beyond a substitution:

- `test_setup_agent_tools.py` tests one devcontainer instead of two, and gains `test_devcontainer_mounts_no_host_data`.
- `.dockerignore` also excludes `.remember` and `.superpowers`, which are machine-local agent state.
- `tasks/README.md` names DESIGN section 9 and a future architecture section, because DESIGN's numbering differs from the collector's.
- [T7](../open/T7.md) carries an open point: `youtube-collector`'s T42 refreshes staging freshness only by a new marker check, but DESIGN 5.11 also accepts a progress report.

## Validation

Environment: the devcontainer image (`docker compose build` of `.devcontainer/docker-compose.devcontainer.yaml`), Docker 29.9.3 on an arm64 Mac, Python 3.14.4, 2026-11-17. The workspace was bind-mounted into a throwaway `docker compose run` container. The creation hook did not run there.

- `./check-coverage.sh -q`: 193 passed, coverage 100% statement and branch for every measured file.
- `mypy media_transcriber`: no issues. `ruff check .`: all checks passed.
- The new mount test failed with a `/Volumes` mount added to the Compose file, and passed without it.
- A preview on the macOS host, outside the devcontainer, failed six tooling tests. The causes were BSD `mktemp -t`, BSD `ln` without `-T`, and the shorter macOS limit on Unix socket paths. The Linux gate run passed all of them.
- The documentation check ran from the host checkout of `agent-workflow-common`, because the creation hook did not run.
- The leftover scan, `git grep -nIiE 'youtube.collector|youtube_collector|COLLECTOR_|yt-dlp|firefox|cookie' -- ':!DESIGN.md'`, found only intended references.
