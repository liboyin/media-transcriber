**Outcome:** Implemented in `d84fb96`, with review fixes shared with T7. The gates passed, every mutant was killed, and the group review ended with no blocking findings.

Outcome: the FastAPI app with every endpoint in [DESIGN section 6](../../DESIGN.md#6-http-api-summary), settings read from `TRANSCRIBER_`-prefixed environment variables, and `python3 -m media_transcriber` running one process. ## Origin and boundary

Accepted for implementation on 2026-11-18, grouped with [T7](T7.md), which holds the [group plan](T7.md#group-plan).

- **Intent:** compose the service: one process that serves the API of DESIGN section 6 and runs T7's worker thread. Submission validates syntactically and never touches the share (5.1). `/health` reports 5.11 from the worker's published record, the database check and a startup check of each profile's accelerator. Settings come from the environment, and profiles from the TOML file of M24.
- **Dependencies:** T7. DESIGN 5.1, 5.3, 5.4, 5.8, 5.9, 5.11, section 6, section 9, A2, A4, A5, and decisions M8, M17, M22 and M24. The collector's `config.py`, `api.py`, `responses.py`, `__main__.py` and `tests/test_main.py` at `9c1b957` are the reference patterns (A2).
- **Implementation direction:**
  - Dependencies: `fastapi` and `uvicorn` at runtime, and the HTTP client that FastAPI's `TestClient` needs in the `dev` group. Each comes with `uv add`.
  - `config.py`, the only module that reads the environment:
    - `Settings.from_environ` reads the variables in the table below. An empty variable takes its default, and an invalid value raises `SettingsError` with the variable's name.
    - `load_profiles` reads the profiles file with `tomllib`. It rejects an unknown key, a duplicate or empty name, an unknown engine, a missing field, a non-scalar decoding value, and a `default` that names no profile. Without a `default`, the first profile is the default. Without the file, the platform's baseline profile is the only one (M24).
  - `languages.py`: `is_well_formed`, the RFC 5646 check that the collector uses.
  - `engine.py`: `EngineAdapter` gains `accelerator_available()`. faster-whisper asks CTranslate2 for a CUDA device, and MLX asks whether Metal is available. Each imports its library only inside the call. The stubs gain the two functions.
  - `responses.py`: response models that forbid undeclared fields, as in the collector.
  - `api.py`: `create_app(settings, components_factory)`, as in the collector.
    - The lifespan initializes the database, starts the worker thread and stops it within the shutdown grace.
    - Store calls run on one dedicated thread.
    - The fatal callback pauses and then ends the process with status 1, through `os._exit`.
    - The endpoints are those of DESIGN section 6, plus `GET /profiles`.
    - `POST /jobs` returns 422 for an invalid path (`validate_request_path`), a malformed tag, an unknown profile, a language that the profile's engine does not support, or an undeclared field. It then stores the job, wakes the worker and returns 202.
  - `__main__.py`: `python3 -m media_transcriber` runs one uvicorn server with the settings. It never starts several worker processes.
  - Tests: `tests/service_process.py` runs the real entry point with fake adapters and the network guard. A fixture starts it on loopback with test-owned storage, and its teardown kills and reaps every child.
- **Settings:**

  | Variable | Meaning | Default |
  |---|---|---|
  | `TRANSCRIBER_STAGING_DIR` | The staging root | required |
  | `TRANSCRIBER_DATABASE` | The SQLite file, never on the share | required |
  | `TRANSCRIBER_WEIGHTS_DIR` | The weights directory, laid out as a Hugging Face cache (M22) | required |
  | `TRANSCRIBER_PROFILES_FILE` | The TOML file of profiles (M24) | the platform's baseline |
  | `TRANSCRIBER_HOST` | The address that the server binds | `0.0.0.0` |
  | `TRANSCRIBER_PORT` | The TCP port | `8000` |
  | `TRANSCRIBER_JOB_RETENTION_DAYS` | How long a finished job stays readable (5.8) | `7` |
  | `TRANSCRIBER_SHUTDOWN_GRACE` | Seconds that shutdown waits for the current job (5.9) | `30` |

- **Decisions within DESIGN's latitude (assumptions):**
  - The database and weights paths have no default. Evidence: the Mac and CUDA deployments (T10, T11) put them in different places, and neither exists yet. Effect: a missing setting fails at startup instead of creating a database in an unexpected place.
  - The accelerator of each profile's engine is checked once at startup, and `/health` reports that result. Evidence: neither library recovers a lost device inside a running process. Effect: `/health` runs no engine code. A profile whose accelerator is unavailable makes `/health` return 503, because its jobs would fail `model`.
  - The engine library versions come from `importlib.metadata`, and a library that is not installed reports null.
  - Staging in `/health` is healthy when the last marker check found the marker, and is not stale under T7's rule. A paused worker is unhealthy.
  - `GET /profiles` lists each profile's settings, whether it is the default, and the sorted language codes of its engine.
  - The host defaults to `0.0.0.0`, as in the collector, because the orchestrator calls the service over the LAN (5.11 and section 9).
  - uvicorn gives open requests 5 seconds after SIGTERM, as in the collector.
- **Compatibility surface:** every HTTP contract of DESIGN section 6, every setting in the table above, and the profiles file are new. Exact JSON schemas are left to the implementation and published at `/docs`. The database layout is T7's.
- **Non-goals:** the production CUDA image and Compose service (T10). The launchd configuration (T11). The benchmark (T9). Authentication (DESIGN section 2). A Docker healthcheck.
- **Validation:**
  - Unit tests of every setting and every profiles-file error.
  - API tests through `TestClient` with fake adapters and a fake worker clock:
    - Each endpoint, each 422 case and each 404.
    - 202 with a job that a later read returns.
    - Health at 200, and at 503 for a failed database, a missing marker, a stale share activity, a failed worker and an unavailable accelerator.
    - A patched staging module proves that no request touches the share.
  - Real-process tests through the fixture:
    - A job that runs to `done`.
    - SIGTERM while idle, and during a job that finishes within the grace.
    - A job that outlasts the grace and is redone after a restart.
    - A fatal worker error that ends the process with status 1.
- **Mutation evidence:** the API never touches the share (5.1, C25). The fatal callback always ends the process (5.9: a process without its worker is never restarted). An invalid path is refused before any job exists (security). `/health` reports 503 for a stale share activity, a paused worker and a failed worker.
- **Done:** the three gates, the review, a closed record, DESIGN's architecture section, and README's status, configuration and running sections. Runs against the real share and real accelerators are host checks (T2, T10, T11).

## Revalidation

On 2026-11-18 at `badc878`, no settings, API or entry point existed, and FastAPI was not a dependency. The user decided that profiles come from a TOML file (DESIGN M24). ## Validation

[T7's record](T7.md#validation) gives the environment and the gates of the shared final candidate `5fb9689`. At `d84fb96`, 541 tests passed with 100% statement and branch coverage, and mypy, ruff, the documentation check and `uv lock --check --offline` were clean.

- API tests run the application's real lifespan and worker thread through `TestClient`, with fake adapters, test-owned storage and a manual monotonic clock.
- `test_no_request_touches_the_share` records Python-level stat, listing and open calls under the staging root. It requires that every one of them comes from the worker thread.
- The lifecycle tests run `service_process.py` as a real child process under the network guard, and check where it imports the package from. They cover a job to `done`, SIGTERM while idle and during a job, and a job abandoned past the grace and repeated after a restart. They also cover a fatal exit with status 1, and a stand-in decoder that must not outlive the service.

## Mutation evidence

The main agent produced it with `mutate.py`. All 9 T8 mutants were killed at `d84fb96`, and again on the tree of `5fb9689` before its docstring fix, through assertions, with no leaked thread.

| Mutant | Invariant | Killing tests |
|---|---|---|
| A submission stats the media | The API never touches the share (5.1) | `test_no_request_touches_the_share` |
| `/health` checks the marker itself | The API never touches the share (5.1) | `test_no_request_touches_the_share` |
| The exit only after a successful pause | The fatal callback always ends the process (5.9) | `test_the_fatal_exit_happens_even_when_the_pause_fails` |
| Exit status 0 | A failed worker exits with status 1 | `test_a_failed_worker_is_unhealthy_and_ends_the_process`, `test_a_failed_worker_ends_the_process_with_status_1` |
| No path validation | An unsafe path is refused with 422 and creates no job | `test_submit_refuses_an_invalid_request_without_creating_a_job` |
| Health ignores staleness, the pause, a failed worker or the accelerator | Each makes `/health` 503 | The matching `test_health_*` and `test_an_unavailable_accelerator_is_unhealthy` tests |

Two runs of the accelerator mutant were invalid. Both tests failed through `assert 200 == 503`, but `mutate.py` read pytest's captured `ERROR` log lines as an errored test. The test now captures its expected error log with its own handler. The run was not reclassified by hand.

## Limitations

- The accelerator of each engine is checked once at startup, so `/health` does not see a device lost later.
- The share-isolation probe sees Python-level calls only, not native code or ffmpeg.
- `tests/README.md` still says that no test starts a real service process. It is a governance file, so its update is proposed to the user instead of made here.
