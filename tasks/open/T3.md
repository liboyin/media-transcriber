# T3: Engine adapter interface and media pipeline

**Priority:** High.

Outcome: the engine adapter interface ([DESIGN section 8](../../DESIGN.md#8-engines-and-platforms)) and engine-neutral timed segments. Also ffmpeg decoding to a mono 16 kHz float32 waveform with the empty-audio failure, the rejection policy, and SRT serialization (DESIGN 5.5 steps 4 and 6 to 8, 5.6 formatting). The pipeline function is the one the worker and the benchmark both call (DESIGN 7.3). Behavior is reimplemented from `youtube-whisperer` at `474f5dc` (DESIGN section 10). A fake engine for tests is part of the task. Paths: `media_transcriber/`, tests. Dependencies: none.

## Origin and boundary

Accepted for implementation on 2026-11-17, grouped with [T6](T6.md) (staging layer) at the user's request. The two tasks share no code. They meet only in the worker (T7).

- **Intent:** implement DESIGN 5.5 steps 4 and 6 to 8 as one engine-neutral pipeline function, which returns the SRT text and the stage timings without touching staging. The worker (T7) publishes the text, and the benchmark (T9) writes it to a result set (DESIGN 7.3, M11).
- **Dependencies:** DESIGN 5.4, 5.5, 5.6, 7.3, section 8 and section 10, and decisions M4, M11, M13 and M18. No task.
- **Implementation direction:**
  - `media_transcriber/engine.py`: the frozen `Segment` (start, end and text in seconds), the `Profile` value (name, engine, model, revision, precision and decoding options), and two protocols. `EngineAdapter` maps a BCP 47 tag to its engine code or `None`, and loads a `TranscriptionModel` for a profile. `TranscriptionModel.transcribe` takes a waveform and an engine language code and returns an iterable of segments that may be lazy.
  - `media_transcriber/audio.py`: `decode_waveform` runs `ffmpeg` as a subprocess, with the source revision's arguments (mono, 16 kHz, signed 16-bit PCM to a pipe, `threads=0`). It reads standard output in chunks and calls an optional `checkpoint` callable after each chunk, for the marker checks of M18. A drain thread keeps the tail of standard error. A non-zero exit raises `DecodingError` with that tail. An empty result raises `EmptyAudioError`. On any exception, including one from `checkpoint`, the function kills ffmpeg, reaps it and joins the drain thread before the exception propagates.
  - `media_transcriber/rejection.py`: the source revision's two rejected substrings, `RejectedTranscriptionError`, and a generator that re-yields segments and raises at the first segment that contains a rejected substring.
  - `media_transcriber/srt.py`: the source revision's formatter. Milliseconds are rounded before decomposition, hours are always present, milliseconds follow a comma, and outer whitespace is stripped from text. Blocks are numbered from 1, and each block ends with an empty line. Consecutive segments with identical text merge into one block that keeps the first start and the last end (DESIGN M19).
  - `media_transcriber/pipeline.py`: `run_pipeline(media, model, language, checkpoint, clock)` decodes, transcribes, rejects, consumes every segment and serializes. It returns the SRT text, the segment count, the audio duration and the decoding, transcription and serialization times. Transcription time includes the rejection check, because both run while the lazy segments are consumed.
  - `tests/fake_engine.py`: a scripted fake model. Its lazy segments record how far they were consumed.
- **Decisions within DESIGN's latitude (assumptions):**
  - ffmpeg runs through `subprocess`, not `ffmpeg-python`. Evidence: the source revision only builds one argument list with it. The package has had no release since 2019 and ships no types. M18 needs chunked reads that it does not offer. Effect: no wrapper dependency.
  - The input is passed as `file:` plus the absolute path, so a title that starts like a protocol name, such as `concat:`, cannot change how ffmpeg opens it.
  - `numpy` becomes a runtime dependency for the waveform. Every engine depends on it already.
  - Rejection stays a whole-run failure and matches the source revision's substrings exactly. Audio that decodes to samples but yields no segments produces an empty SRT text, as at the source revision.
  - A negative timestamp raises `ValueError`, where the source revision used an assertion that `python -O` removes.
- **Compatibility surface:** none. No HTTP contract, setting or on-disk layout exists yet. Python modules are internal.
- **Non-goals:** a real engine adapter (T4, T5), language-tag validation and profile configuration (T8), model residency and job durations (T7), publication (T6) and benchmark loops (T9).
- **Validation:** unit tests with the fake engine. Decoding tests run ffmpeg only on synthetic audio that the test creates in `tmp_path`, including a clip with zero samples and a file without an audio stream. Tests cover byte-exact SRT output against the source revision's rules, rejection before serialization, full consumption of lazy segments, and ffmpeg reaped after an exception from `checkpoint`.
- **Mutation evidence:** the rejection check stops the run before any SRT text exists (incorrect acknowledgement). The pipeline consumes every segment before it returns (incorrect acknowledgement). ffmpeg is killed and reaped when decoding is interrupted (resource ownership).
- **Done:** the three gates, the review, a closed record, and DESIGN's new architecture section. The real decoding of recordings and a real engine are host checks of T4, T5 and T9.
