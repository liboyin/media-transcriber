# T5: MLX Whisper adapter

**Priority:** High.

Outcome: an MLX Whisper adapter with full `large-v3` ([DESIGN section 8](../../DESIGN.md#8-engines-and-platforms), M13), installed only on macOS through a platform marker or an optional group. In the devcontainer the adapter is type-checked against a narrow stub or override and tested with a fake. mlx-whisper depends on torch, so measure the lock and image-size impact before choosing how it is declared. The [MLX smoke test](T2.md#mlx-smoke-test) showed that full `large-v3` fits on the M2 Mac. A contract test against a real model is a Mac host check (T2). Paths: `media_transcriber/`, `pyproject.toml`, `uv.lock`, tests. Dependencies: T3.

## Origin and boundary

Accepted for implementation on 2026-11-17, grouped with [T4](T4.md) (faster-whisper adapter). T4 holds the [shared constraints](T4.md#shared-constraints) on languages, weights, types and profile checks, and the [group plan](T4.md#group-plan).

- **Intent:** implement the `EngineAdapter` protocol of [T3](../closed/T3.md) for MLX Whisper on Apple silicon, with full `large-v3` in `float16` (DESIGN section 8, M13, M23). The adapter loads offline from the weights directory (M22).
- **Dependencies:** T3, T4's shared modules, DESIGN 5.4, 5.5, section 8 and section 9, and decisions M13, M22 and M23.
- **Implementation direction:**
  - `pyproject.toml` declares `mlx-whisper; sys_platform == 'darwin'` as a runtime dependency. The [measurement](#dependency-measurement) favors the marker over an optional group.
  - `media_transcriber/mlx_whisper_adapter.py`: `MlxWhisperAdapter(weights_dir)` with the engine name `mlx-whisper`, and `BASELINE_PROFILE`. The module imports `mlx_whisper` and `mlx.core` only inside `load` and `transcribe`, so it imports on Linux without them.
  - `load` checks the profile and maps the precision to mlx-whisper's `fp16` flag: `float16` or `float32`, else `ValueError`. It resolves the weights, drops the model that `mlx_whisper.transcribe.ModelHolder` holds, and loads the new one through `ModelHolder.get_model(<directory>, <dtype>)`.
  - mlx-whisper 0.4.3's `transcribe` always takes its model from `ModelHolder`, which caches one model by path alone and ignores the dtype. Dropping the held model first makes `load` honor a changed precision, and frees the old model before the new one is loaded.
  - The loaded model calls `mlx_whisper.transcribe(waveform, path_or_hf_repo=<directory>, fp16=<flag>, language=<code>, task="transcribe")` with the library's other defaults. It maps the returned segments to `Segment`. mlx-whisper returns a list, not a lazy iterator.
  - Before transcribing, the loaded model checks that `ModelHolder` still holds its model, and raises `RuntimeError` otherwise. Without that check, a model object replaced by a later `load` would transcribe silently with the newer model.
  - `BASELINE_PROFILE` is `mlx-community/whisper-large-v3-mlx` at revision `49e6aa286ad60c14352c404340ded53710378a11`, `float16`, with no decoding settings. It is the model and revision of the T2 smoke test.
- **Decisions within DESIGN's latitude (assumptions):**
  - The adapter accepts no decoding settings, as in T4.
  - The adapter relies on `ModelHolder`, which is not documented as public. Evidence: `transcribe` offers no other way to pass a loaded model. Effect: an mlx-whisper upgrade that changes it fails the stub check of the host check, or the adapter at run time.
- **Compatibility surface:** the layout of the weights directory (M22), shared with T4. No HTTP contract or setting exists yet.
- **Non-goals:** profile configuration and the adapter registry (T8), model residency across jobs (T7), Metal checks for `/health` (T8), quantized or turbo profiles, and the Mac deployment (T11).
- **Validation:** unit tests install fake `mlx_whisper` and `mlx.core` modules through `monkeypatch`. The fake `ModelHolder` keeps the real one's cache by path alone. Tests cover the arguments, the precision mapping and the reload after a precision change. They also cover the check for a replaced model, the segment mapping, and the import without MLX.
- **Mutation evidence:** loading never reaches the Hub: `ModelHolder` and `transcribe` get the resolved directory, never the repository name. A changed precision loads a new model. A replaced model refuses to transcribe (resource ownership).
- **Done:** the three gates, the review, a closed record, and DESIGN's architecture section. The contract test against the real model and the check of the MLX stub are Mac host checks, recorded in T2.

### Dependency measurement

Measured on 2026-11-17 in a scratch copy of `pyproject.toml` and `uv.lock` at `c1ec7e5`, with uv 0.13.7, after faster-whisper was added (T4):

| Declaration | Packages in the lock | Lock size | Linux runtime venv |
|---|---|---|---|
| Before T4 | 20 | 502 lines | 52 MB |
| faster-whisper only | 41 | 841 lines, 149 KB | 310 MB |
| Plus `mlx-whisper; sys_platform == 'darwin'` | 61 | 1140 lines, 186 KB | Unchanged: no MLX or torch package |
| Plus `mlx-whisper` in an optional group | 80 | 1669 lines, 299 KB | Unchanged unless the group is requested |

- With the marker, uv locks torch with its 4 macOS wheels only.
- The optional group without a marker also locks Linux torch and 15 NVIDIA packages, because uv resolves every group for every platform.
- On the Mac, the marker adds 20 packages. Their locked macOS arm64 wheels add up to about 302 MB to download, of which torch is 139 MB and mlx-metal 78 MB. The installed size on the Mac was not measured.
- The devcontainer image and the future CUDA image therefore grow only by faster-whisper, about 260 MB on arm64 Linux.
