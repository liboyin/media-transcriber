# T4: faster-whisper adapter

**Priority:** High.

Outcome: a faster-whisper adapter with the CUDA `float32` sequential baseline profile, as at the `youtube-whisperer` source revision ([DESIGN section 8](../../DESIGN.md#8-engines-and-platforms), M13), and the language mapping of DESIGN 5.4. Adds the faster-whisper dependency. Tests use fakes. A contract test against a real model is a CUDA host check (T2). Paths: `media_transcriber/`, `pyproject.toml`, `uv.lock`, tests. Dependencies: T3.

## Origin and boundary

Accepted for implementation on 2026-11-17, grouped with [T5](T5.md) (MLX Whisper adapter) at the user's request. This file holds the [shared constraints](#shared-constraints) and the [group plan](#group-plan).

- **Intent:** implement the `EngineAdapter` protocol of [T3](../closed/T3.md) for faster-whisper on CUDA, with the source revision's settings (DESIGN section 8, M13). The adapter maps a BCP 47 tag to a Whisper code (DESIGN 5.4), and loads a profile's model offline from the weights directory (DESIGN section 9, M22).
- **Dependencies:** T3, DESIGN 5.4, 5.5, section 8 and section 9, and decisions M13 and M22.
- **Implementation direction:**
  - The [shared modules](#shared-constraints) `whisper_languages.py` and `weights.py` land with this task.
  - `media_transcriber/faster_whisper_adapter.py`: `FasterWhisperAdapter(weights_dir)` with the engine name `faster-whisper`, and `BASELINE_PROFILE`. `load` checks the profile, resolves the weights, and builds `faster_whisper.WhisperModel(<directory>, device="cuda", compute_type=<precision>, local_files_only=True)`.
  - The loaded model calls `WhisperModel.transcribe(waveform, language=<code>, task="transcribe")` with the library's other defaults, as the source revision did. It returns the library's lazy segments, mapped lazily to `Segment`.
  - `BASELINE_PROFILE` is `Systran/faster-whisper-large-v3` at revision `edaa852ec7e145841d8ffdb056a99866b5f0a478`, `float32`, with no decoding settings. faster-whisper maps the source revision's `large-v3` to that repository. The revision is the repository's `main` on 2026-11-17, from the Hub's public metadata.
  - faster-whisper becomes a runtime dependency for every platform. DESIGN restricts only MLX to one platform.
- **Decisions within DESIGN's latitude (assumptions):**
  - The device is always `cuda`. DESIGN section 10 drops the CPU path. Effect: loading on a host without CUDA fails, which the worker (T7) reports as category `model`.
  - The baseline needs no decoding settings, so the adapter accepts none yet. A profile with any decoding setting fails at `load` with `ValueError` (the T3 `Profile` contract). Effect: a later candidate profile, such as a batched one (DESIGN section 8), adds its settings with its own task.
  - The precision passes to CTranslate2 unchanged, which rejects an unknown type. Evidence: CTranslate2 owns the list of compute types.
- **Compatibility surface:** the layout of the weights directory (M22) is new. No HTTP contract or setting exists yet. Python modules are internal.
- **Non-goals:** profile configuration, the setting for the weights directory and the adapter registry (T8). Engine versions and accelerator checks for `/health` (T8). Model residency (T7), batched profiles, and a CPU path.
- **Validation:** unit tests with a fake `WhisperModel` patched into the module. The fake is `create_autospec` of the installed class, so a call that the real signatures reject fails. It yields the library's own `Segment` dataclass. The tests cover the constructor arguments, the transcription arguments, lazy mapping of segments, and the profile checks. The [shared modules](#shared-constraints) have their own tests.
- **Mutation evidence:** loading never reaches the Hub (DESIGN section 9): `WhisperModel` gets the resolved directory and `local_files_only=True`. Segments stay lazy until consumed, so the pipeline's full consumption stays meaningful (incorrect acknowledgement).
- **Done:** the three gates, the review, a closed record, and DESIGN's architecture section. The contract test against a real model is a CUDA host check, recorded in T2. It waits for the CUDA machine (M15).

### Shared constraints

These hold for T4 and [T5](T5.md):

- **Languages.** `media_transcriber/whisper_languages.py` holds the 100 Whisper language codes and `whisper_language(tag)`. The function lowercases the primary subtag of a well-formed tag and returns it if Whisper supports it, else `None` (DESIGN 5.4). faster-whisper 1.2.1 and mlx-whisper 0.4.3 list the same 100 codes, which was checked on 2026-11-17 against both packages' sources. A test compares the table with the installed faster-whisper. Assumption: there are no aliases, so `jv` (Javanese) is unsupported although Whisper knows it as `jw`. DESIGN 5.4 names the primary subtag only.
- **Weights.** `media_transcriber/weights.py` holds `resolve_weights(weights_dir, profile)`. It calls `huggingface_hub.snapshot_download` with the profile's model and revision, `cache_dir=weights_dir` and `local_files_only=True` (M22). A missing snapshot raises `WeightsNotFoundError`, a `FileNotFoundError` that names the model, the revision and the directory. On 2026-11-17, a trace under strace showed that the offline call opens only paths in the cache directory and makes no connection. `huggingface-hub` becomes a direct dependency, because the application imports it.
- **Types.** Neither engine library ships type information. Narrow stubs in `stubs/` declare only the names that the adapters use, and `mypy_path` points at them. A stub keeps mypy's checks, where an `ignore_missing_imports` override would make every use `Any` (AGENTS.md design rules). mypy's `stubtest` reports every parameter that a narrow stub omits, so it cannot check these stubs. The faster-whisper tests check the calls instead, as the validation below states. The MLX stub can only be checked by the T5 host check.
- **Profile checks.** Each adapter rejects a profile for another engine with `ValueError` before it touches the weights directory.
