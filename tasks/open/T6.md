# T6: Staging layer

**Priority:** High.

Outcome: resolution of request paths inside the staging root, including symlinks (DESIGN 5.2), and the `.media-transcriber-root` marker check (DESIGN 5.10). Also the `NEVER` existing-SRT check and atomic staged publication through pathlib-extensions' `StagedFile` (DESIGN 5.6). Adds the pathlib-extensions dependency. Paths: `media_transcriber/`, `pyproject.toml`, `uv.lock`, tests. Dependencies: none.

## Origin and boundary

Accepted for implementation on 2026-11-17, grouped with [T3](T3.md), which holds the group plan.

- **Intent:** give the worker (T7) every staging operation that it needs, and nothing that decides job state. That covers the marker check, the resolution of a request path inside the root, the `NEVER` preflight and atomic publication of SRT text. DESIGN 5.2, 5.5 steps 1 to 3 and 8, 5.6, 5.10, M7, M8 and M9 apply.
- **Dependencies:** DESIGN 5.1, 5.2, 5.5, 5.6, 5.10 and 5.11, and decisions M7, M8, M9, M18 and M20. No task.
- **Implementation direction:** one module, `media_transcriber/staging.py`:
  - `validate_request_path` checks syntax only and never touches the filesystem, so the API (T8) can use it (DESIGN 5.1). It rejects an empty path, an absolute path, a `..` component, a hidden component, a NUL character and a backslash.
  - `require_marker(root)` raises `StagingUnavailableError` if the marker is missing or the root cannot be read. It never creates the marker.
  - `resolve_job_paths(root, path)` returns the media path and the SRT path. The SRT path is the requested path with the suffix `.srt`. The function raises `MediaNotFoundError` if the media file does not exist. It raises `PathOutsideRootError` if either path resolves outside the root, also through a dangling symlink.
  - `srt_exists(paths)` applies the `NEVER` preflight with `OverwritePolicy.NEVER.resolve`.
  - `publish_srt(paths, text, checkpoint)` calls `checkpoint` first, then raises `MediaNotFoundError` if the media file is gone (DESIGN M20). It then writes the UTF-8 text in chunks inside `StagedFile` under `NEVER` and calls `checkpoint` between the chunks (M18). It returns whether it published, or found a competing file and kept it.
  - pathlib-extensions comes from `git+https://github.com/liboyin/pathlib-extensions.git`, as at the source revision. `uv.lock` pins its commit. The package ships no type information, so `pyproject.toml` gets a narrow mypy override for `pathlib_extensions`.
- **Decisions within DESIGN's latitude (assumptions):**
  - `StagedFile` creates missing parent directories. The check that the media file still exists (DESIGN M20) also keeps its directory in place, so publication creates no directory, except in a race with a move.
  - The SRT is written as UTF-8 with no newline translation. The source revision used the locale's default encoding.
  - The SRT path keeps the requested name, not the name of a symlink's target, so the SRT sits beside the name that the user sees.
  - Only one process writes into a deployment's staging root at a time. A path that changes between the containment check and publication is not defended against.
- **Compatibility surface:** none yet. The marker name `.media-transcriber-root` and the SRT naming rule are product contracts from DESIGN 5.6 and 5.10. They are implemented, not changed.
- **Non-goals:** job states, failure categories, pausing and health (T7), the API (T8), and the removal of stage directories left by an abrupt exit (DESIGN 5.6).
- **Validation:** tests on `tmp_path` with the real `StagedFile`. They cover each rejected path form, and symlinks and dangling symlinks that escape the root. They cover a missing marker, an unreadable root and an existing SRT. They cover a competing file created from `checkpoint` during publication, a failed write, and the removal of the stage directory on every exit.
- **Mutation evidence:** `NEVER` never replaces an existing or competing file (data loss). Containment rejects escape through a symlink (security). The marker is checked before publication (data loss on an unmounted share). A failed write publishes nothing and leaves no stage directory (incorrect acknowledgement).
- **Done:** the three gates, the review, a closed record, and DESIGN's architecture section. Hard links on the Mac's SMB mount, which `NEVER` publication needs, are a host check that the user is running before implementation. A full publication on the real share is a host check (T2).
